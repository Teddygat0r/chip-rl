# Experimental fused INT8 dot + bias + requant (v29)

One command computes one scalar output. `candidate #(parameter K=4)` has input `clk,rst,in_valid,out_ready,in_data[511:0]` and output `in_ready,out_valid,out_data[31:0]`. The trusted host sets K to 1,2,4,8 or16; a candidate action supplies only complete synthesizable RTL source. Every byte `a[i]` in bits `8*i+:8` and `b[i]` in bits `128+8*i+:8` is signed INT8; only indices below K are used. Signed INT32 bias occupies bits256..287; unsigned INT16 scale288..303; unsigned shift304..309 (accepted values0..47); signed INT8 zero point310..317. Bits318..511 and operands at indices>=K are ignored. No lane mask exists.

Compute the dot with exact integer arithmetic, add bias without overflow in at least33 signed bits, multiply by unsigned scale without overflow in at least49 signed bits, divide by2**shift with round-to-nearest ties-to-even, add zero point exactly, then clamp to signed INT8 [-128,127]. The entire 32-bit output must sign-extend that INT8 value. Scale0 yields the clamped zero point. Negative ties round toward the even integer. Invalid shifts are outside the generated accepted-input domain. Unused input bits may carry arbitrary values.

An input command is accepted on a positive edge only when reset is low and `in_valid && in_ready`. Each accepted command produces exactly one in-order, registered response at least one later edge; `out_valid && out_ready` consumes it. While stalled, `out_valid` and all output bits remain stable. Synchronous active-high reset has priority over acceptance and retirement: ready/valid are suppressed while asserted, its next rising edge cancels every pending or stalled command and their progress counters, and no canceled response may appear after release. The producer holds an offered command until acceptance. There is no fixed-cycle equivalence obligation between valid architectures.

For a scored command accepted at cycle `a`, define its **service-opportunity age** at cycle `t` as `sum(out_ready[u] for u=a+1..t)` while that command remains pending; the ready-high consumption cycle is included. The accepted cycle itself is excluded. An accepted command fails the finite progress check if that age exceeds `K+64`. Ready-low cycles never increment this per-command counter. Output value/order/stability checks still run on every cycle, including ready-low cycles. A separate whole-run watchdog uses the actual generated readiness sequence: starting with the last scheduled release cycle, it allows `N*(K+64)+1` ready-high cycles for `N` released commands. If offered work remains unfinished when that service opportunity budget is exhausted, the run fails. This is a finite test bound, not an unlimited-liveness proof. Tool process wall timeouts remain infrastructure limits and never count as correctness passes.

The scored v28 operand/release/ready **prefix** is frozen. A development evaluation scores K=2,4,8; a heldout evaluation scores K=1,2,4,8,16. A host-selected target K outside the development set is added there. The agent's RTL action cannot change that set. Each development configuration releases 174 commands with increments from `(0,0,1,2)` and `out_ready = (cycle % 11 >= 3)`; heldout releases 206 commands with increments from `(0,0,0,3,5)` and `out_ready = (cycle % 13 >= 5 && cycle % 53 >= 6)`. The ready file extends beyond that scored prefix only to implement the service-based whole-run watchdog. Unscored probes include an accepted command held against 257 ready-low cycles, recovery with fresh work, and a separate reset while work/output is blocked followed by fresh work. Scored counters exclude these probes and the separate saturated 32-command stream.

The trusted testbench directly records accepted and consumed counts, ready-low cycles, output-blocked (`out_valid && !out_ready`) cycles, and input-blocked (`in_valid && !in_ready`) cycles. It reports accepted-to-first-presentation and accepted-to-consumption ages separately, both in raw cycles; it also reports accepted-to-consumption service-opportunity ages. Offered-to-consumption latency runs from scheduled release to output consumption, so it includes producer queueing, computation and output blocking. The always-ready 32-command stream gives initiation interval `(last_accept-first_accept)/31`. RTL and mapped-netlist outputs **and metrics** must agree exactly.

The **experimental balanced proxy reward** uses only trusted, verified paired scored cases and a fixed serial baseline. In each case, `rA = candidate generic cells / baseline generic cells` and `rC = candidate workload completion cycles / baseline completion cycles`. Hard constraints are `rA <= 4`, `rC <= 1`, and candidate stream II `<= K+4`, checked for every case. A correctness, structural, service-progress, missing-baseline, invalid-metric or hard-constraint failure returns reward 0 and `reward_qualified=false`. For correct cases meeting all constraints, the score is `max(0, 1 - exp(mean(log(rA*rC))/2))`, with equal weight for all declared scored cases. A verified baseline is qualified with score0; score0 alone does not mean incorrect. The result exposes per-case raw ratios, each constraint, qualification and score separately. Candidates do not set goals, baselines, replay seeds or scored cases through the RTL action.

Generic mapped cells and logic depth are synthesis proxies, workload cycles are simulation counts, and the reward is not routed timing, physical area, energy or power. Formal and physical checks are not run. The evaluator imposes source, CPU, memory, file-size and wall-time limits but offers no OS sandbox against a same-UID agent with writable access to trusted files. It is not qualified for arbitrary unisolated agents or silicon use.
