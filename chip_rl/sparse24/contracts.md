# Compressed 2-of-4 signed INT8 dot+bias+requant (experimental)

One command computes one scalar output. `candidate #(parameter G=4)` uses `clk,rst,in_valid,in_ready,in_data[511:0],out_valid,out_ready,out_data[31:0]`. The trusted host chooses any integer G from 1 through 8; a candidate action supplies only complete synthesizable RTL. Development scores G={1,2,4}; the v35 heldout parameter comparison scores G={3,5,6,7}, plus the host target G if it is outside that set. The earlier G={1,2,4,8} heldout records remain historical v32 evidence. Eight 56-bit group slots fill bits0..447. For slot g, at base bit `56*g`, offsets0..7,8..15,16..23,24..31 hold signed INT8 activations a0,a1,a2,a3; offsets32..39 and40..47 hold compressed signed INT8 weights w0,w1; offsets48..50 hold a 3-bit selector; offsets51..55 are ignored padding. Slots g>=G are ignored in full.

Selector values0..5 map w0,w1 to these **ordered ascending activation-position pairs**: 0→(0,1), 1→(0,2), 2→(0,3), 3→(1,2), 4→(1,3), 5→(2,3). For example, selector1 contributes `a0*w0 + a2*w1`, and selector4 contributes `a1*w0 + a3*w1`. Selectors6 and7 are reserved-zero: their entire group contribution is exactly0 regardless of activations and weights. There is no per-group mask or sign reinterpretation. Padding must not affect the result.

The global signed INT32 bias occupies bits448..479, unsigned INT16 scale480..495, unsigned shift496..501 (generated accepted values0..47), and signed INT8 zero point502..509. Bits510..511 are ignored. Form the exact sum of the G group contributions and bias in at least signed33 bits, multiply by the unsigned scale in at least signed49 bits, divide by2**shift using round-to-nearest ties-to-even, add zero point exactly, saturate to signed INT8, then sign-extend to all32 output bits. Negative ties must round to the even integer. Scale0 yields the clamped zero point. Invalid shifts are outside the generated accepted-input domain.

An input is accepted on a positive edge only when reset is low and `in_valid && in_ready`. Each accepted input yields exactly one in-order registered response at least one later edge; `out_valid && out_ready` consumes it. While blocked, `out_valid` and all32 data bits remain stable. Synchronous active-high reset suppresses ready/valid immediately, clears pending valid work at the next edge, and cancels every pending or blocked response. The producer holds an offered input until acceptance. No fixed-cycle equivalence is required between valid architectures.

The trusted testbench checks exact oracle values and handshakes at RTL and Yosys-mapped level. It counts ready-high service opportunities strictly after each acceptance, including the consuming cycle, and rejects a still-pending request only after `G+64` such opportunities. Ready-low cycles do not advance that age. Output correctness/order/stability are checked even during ready-low cycles. A separate whole-run watchdog allows `N*(G+64)+1` ready-high cycles from the last scheduled release for N offered commands. A 257-cycle consumer stall, reset while work/output is blocked, fresh recovery, ordered scored stream and separate always-ready 32-command stream are checked. Tool timeouts and incomplete proof never count as passes.

The Python reference independently expands each selector to a dense four-weight vector and performs an ordinary exact dot before quantization. Directed and seeded cases exercise all eight selectors at every active group, the six pair positions, reserved-zero behavior, distinct signed activations, permutations of active groups, ignored padding/inactive slots/top bits, signed extremes, ties, saturation, and scale/shift/bias edges. Development and heldout operands are separately seeded; the trusted host chooses replay seeds and evaluation cases.

The evaluator reports direct accepted/consumed counts, ready-low/output-blocked/input-blocked cycles, accepted-to-first-presentation and accepted-to-consumption latency, release-to-consumption latency, separate stream II, generic Yosys/ABC cell count and generic logic-depth diagnostic. A separate unscored decoder check exercises every selector and active group with tagged activations and three weight patterns. Both RTL and mapped netlist must match the independent dense-expansion oracle.

The experimental reward is computed only from verified paired cases. For each declared G, area ratio rA is candidate generic cells divided by fixed serial generic cells, completion ratio rC is candidate workload cycles divided by fixed serial cycles, and stream II is measured separately. Every case must satisfy rA <= 4, rC <= 1, and stream II <= 2*G+4. A correctness, resource, progress, or gate failure returns reward 0 and reward_qualified false. Otherwise reward is max(0, 1 - exp(mean(log(rA*rC))/2)), with equal case weights. The baseline scores 0. The response includes raw ratios and per-gate outcomes; tested_correct and validation distinguish functional pass from service-target failure. Missing or unverified baseline metrics cannot produce a positive reward. These are finite synthesis/simulation proxies, not routed area, delay, Fmax, power or physical validation. Formal and physical stages are not run. Source sanitizer and process limits do not provide OS isolation against a same-UID agent with access to trusted files.
