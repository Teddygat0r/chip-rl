# Five-family pilot: independent RTL review packet

**Status: prepared for review; no independent human RTL review has been requested, performed, or endorsed.** This packet is a checklist, not a signoff. The five proposed families are `gather`, `mshr`, `sparse24_dot_requant` (short name `sparse24`), `block_quant`, and `hadamard_int8`. The repository contracts and implementation are authoritative; the read-only pilot contract inventory at commit `fc6f03ca2ddbe4cb0ffaf297cd7c1df72030823e` is a navigation aid, not independent verification. Review against the exact frozen source and evaluator revision recorded under the [experiment protocol](pilot-experiment-protocol.md). No candidate, oracle, score, or workload should change in response to test findings without a new version and a new freeze.

## What the reviewer must return

For **each** family, record the exact source and contract hashes reviewed; reviewer identity and affiliation; review date; files/parameter values inspected; a pass, fail, or unresolved judgment for each item below; minimal counterexamples for failures; and the scope of any dynamic checks actually run. An RTL read, a source simulation, a mapped simulation, bounded formal, and physical implementation are different evidence. Blank cells and unanswered questions mean **pending**, never implicit approval. A reviewer should be independent of the RTL/evaluator authors and able to challenge the baseline and oracle; an author explanation is not an independent endorsement.

### Cross-family checklist

- [ ] Confirm the public action is a complete synthesizable `candidate` source, with the exact module, parameters, port widths and host-owned configuration. The agent cannot set private replay seeds, workloads or scoring through its action. Check parser/sanitizer limits separately from OS isolation; same-UID access to trusted files is not solved by source screening.
- [ ] Trace all accepted-input, pending-work and output states across backpressure, including acceptance and retirement on the same edge where permitted. No accepted request may be lost, duplicated, invented, or answered from an unaccepted input. Check minimum registered latency where specified, in-order completion for four block/transaction families, and tag-based possible reordering for MSHR.
- [ ] Check synchronous active-high reset at the port and at the active edge. Verify cancellation of a pending computation, a blocked output, multiple outstanding requests and a fresh post-reset transaction. For MSHR, reset is **coordinated** with the external memory service; a unilateral reset plus stale response is outside the current contract.
- [ ] Verify every required output bit, including zero padding and sign extension, and ignored input bits. Look for X/Z on valid outputs and unstable payloads while stalled. Check finite progress/watchdog conditions without treating a timed-out or unobserved request as a pass.
- [ ] Derive representative expected results without executing the RTL or its scheduling algorithm. Inspect whether the host oracle and directed cases can miss a shared sign, rounding, packing, reset, or selector mistake. If an oracle shares the RTL's decomposition, require a second independent formulation or hand calculation.
- [ ] Run or inspect negative controls for the **specific** bug class claimed. A rejected mutant proves only that the checked finite campaign catches that mutant. Check both source RTL and mapped netlist where the qualification claims both; compare outputs, transactions and measured counters, and record any divergence.
- [ ] Review the fixed baseline as an engineering comparator: its avoidable muxes, serialization, duplicated arithmetic, capacity assumptions and area/latency tradeoffs. State whether a gain is plausibly baseline-specific. Do not turn a generic-cell or simulated-cycle ratio into physical PPA, silicon readiness, policy learning, or generalization to unseen architectures.

## Family-specific specification and adversarial cases

| Family and normative source | Contract points to verify | Directed corners and protocol probes | Baseline weakness to challenge |
|---|---|---|---|
| [`gather`](../chip_rl/contracts.md) | `candidate #(WIDTH=16,DEPTH=256,K=4)` uses the pilot 512-bit command/256-bit response. Four masked 8-bit addresses select reset-zero 32-bit words modulo DEPTH; reads compact active lanes in original lane order, preserving duplicates; writes return zero. Response count is bits 0..2, packed words start at bit 8. Exactly one ordered response/accepted command, 1..64-cycle latency, stable output under stall. | Empty/one/sparse/full masks; repeated and wraparound addresses; write then read; reset after dirty memory and blocked output; back-to-back operations, producer-held input and 64-cycle boundary. Check ignored high fields and zero unused output bits. Separate reset cancellation from the v27 elastic-only repair: v27 inspected gather but added **no** gather-specific single-edge cancellation gate. | The fixed register-array design presents four irregular reads and variable compaction/destination indexing; `time_mux` changes area/latency. Historical v1 cell numbers are superseded; there is no retained raw gather result in this snapshot. |
| [`mshr`](memory-v12.md) / [`port spec`](../chip_rl/memory/spec.py) | `candidate #(ENTRIES=4)`; ENTRIES 2/4/6/8. Eight-bit unique outstanding client tags, 16-bit **word** addresses; aligned four-word line fetch and 128-bit memory return, four-bit transaction IDs. At most one outstanding fetch per line, up to four merged waiters/line; client results may reorder and must retain each tag/data, fault zero. The two memory channels and client output obey independent ready/valid stability. | Same-line four-word merges and fifth waiter backpressure; concurrent distinct lines up to ENTRIES; out-of-order returns; memory ID reuse only after response; reset with merged requests, memory request/output blocked and poisoned inactive inputs, then fresh recovery. Do not inject uncanceled pre-reset memory responses after coordinated reset. Check 2048-cycle accepted-request deadline. | `ring` baseline uses per-entry state, four-slot circular waiters, linear match/free scans and a single output register. `shift` is a near-area alternative, not evidence of a broadly hard optimization problem. |
| [`sparse24`](../chip_rl/sparse24/contracts.md) | `candidate #(G=4)` with G 1..8. Each 56-bit group has four signed INT8 activations, two ordered signed INT8 weights and selector 0..5 for pairs (01,02,03,12,13,23); 6/7 contribute **zero**. Bits 51..55 and groups beyond G are ignored. Add signed INT32 bias, multiply unsigned INT16 scale in sufficient signed width, shift 0..47 with nearest ties-to-even (including negative ties), add signed INT8 zero point, clamp INT8 and sign-extend all 32 output bits. | All selectors at every active group, active-group permutations, padding/inactive/top-bit invariance; signed extrema, negative ties, zero scale, large shift, bias/scale overflow boundaries, saturation. Ordered registered response, blocked stability, reset cancellation, 257-cycle output stall, fresh recovery, service bound G+64 ready-high opportunities. | `serial` spends 2G MAC cycles and one block at a time. Four-stage `pipeline` trades replicated arithmetic area for throughput; any improvement must be compared against that architectural alternative, not called intrinsically learned. |
| [`block_quant`](../chip_rl/block_quant/contracts.md) | `candidate #(N=4)`, N 1..16. Max of signed INT16 magnitudes must represent `abs(-32768)=32768` in at least 17 bits. Exponent `s=max(0,bit_length(max)-7)`; round each signed lane divided by 2^s to nearest ties-to-even, then clamp to INT8. Output has active bytes at `8*i`, zero inactive bytes, exponent at bits 128..131, all bits 132..255 zero. | Zero, 127/128, 255/256 and every exponent transition through 32768; positive/negative halfway values, round-then-clamp, each maximum lane, ignored high inputs, zero padding. Ordered registered handshake, reset during blocked work/output, 257-cycle stall, <=2N+64 ready-high opportunities. | `serial` scans then quantizes a lane/cycle; `chunked4` reduces quantization cycles; `parallel` is much faster but fails the frozen N16 4× generic-cell area gate. Chunked4's documented N4 completion margin is workload-sensitive. |
| [`hadamard_int8`](../chip_rl/hadamard_int8/contracts.md) | `candidate #(N=4)`, N in {1,2,4,8,16}. Signed INT8 lanes yield exact signed INT16 `y_j=sum_i (-1)^popcount(i&j)*x_i`, unnormalized Sylvester order, with no rounding or saturation and zero inactive output bits. N1 sign-extends without a work cycle. | Basis vectors; all `-128`/`127`; sign and output-lane permutations; intermediate overflow/truncation; ignored input bits and zero inactive lanes. Input must be latched despite changed wires in flight. Check blocked stability, 257-cycle stall, reset while blocked, one ordered registered output/request, bound 2B+32 ready-high opportunities for B=(N/2)log2(N). | `serial_butterfly` spends B work cycles and uses a fixed 16-lane workspace/dynamic indexing; `stage_parallel` trades area for latency, fails N16 4× area gate despite fast II. The references are not best-known architectures. |

## Oracle and existing-control evidence to inspect, without promoting it to proof

- **Gather:** the separately implemented Python `Model.step` and generated RTL, hand-calculated model tests, source/mapped replay and mandatory long streams are described in the [pilot contract](../chip_rl/contracts.md). The [adversary generator](../chip_rl/adversaries.py) contains `no_reset`, `ignore_late_writes`, and `gather_order` controls. Check current executed artifacts before claiming a particular control passed. No raw gather result is retained in this snapshot.
- **MSHR:** the [memory report](memory-v12.md) describes a dictionary-based oracle and tag/memory-token scoreboard, plus finite mutant rejection. The [v27 reset audit](reset-audit-v27.md) specifically preserved `two_edge` and conditional retained-state bad sources, rejected them in source and mapped simulation, and accepted both ring and shift after the repair. This says nothing about unilateral reset.
- **Sparse24:** the [dense-expansion oracle](../chip_rl/sparse24/oracle.py) and [contract](../chip_rl/sparse24/contracts.md) require scalar decoder probes and source/mapped comparison. The [v34 decoder-only summary](../evidence/v34/summary.json) excludes the MAC, requantizer and handshake/reset RTL. Historical v35 heldout G qualification is reported in [current status](current-status.md), but its original report is absent here; do not label it an independently reviewed full proof.
- **Block quant:** [v37](block-quant-reward-v37.md) reports source/mapped rejection of wrong `-32768` magnitude and ties-away controls; [v38](block-quant-sensitivity-v38.md) repeated exact source/mapped checks on three seeds. The earlier reset-probe bug and its repair are part of the evidence to audit, not something to omit.
- **Hadamard:** the direct parity-matrix oracle was cross-checked against an iterative butterfly oracle. [Phase 2](hadamard-int8-v1-phase2.md) reports three predeclared arithmetic controls—wrong sign, swapped lanes, signed8 truncation—failing source and mapped numerical checks. None establishes reset safety beyond finite probes or physical qualification.

Source simulation tests the RTL with the present finite inputs and handshakes. Mapped simulation tests a Yosys/ABC transformation of that RTL under the same finite scope; agreement is valuable but is neither unbounded equivalence nor proof against a shared oracle error. Generic cells/logic depth and simulated cycles are proxies. No five-family routed PPA, power, unbounded formal proof, third-party adjudication, or trained-policy gain is established. The bounded two-design integer-RMS physical reference in [this report](rms-physical-reference-v1.md) is outside this five-family set and had incomplete reference-deck DRC; it cannot validate this pilot's proxy-to-physical correlation.
