# Five-family pilot experiment protocol (model and validation gates pending)

**Status: prospective model and full-validation protocol, with limited reference checkpoints complete.** The frozen authored/legacy references passed a 37-case TRAIN panel and 65-case reference-only DEV/TEST qualification; a ten-design exploratory TRAIN routed-area study is complete ([checkpoint](five-family-pilot-checkpoint.md), [physical report](pilot-physical-calibration.md)). These are finite reference and area observations, not a model experiment or a clearance of Gate 3. No model-difficulty measurement, weight-updated policy training, general physical-proxy validation, or independent human RTL signoff has been performed. The [review packet](pilot-review-packet.md) is a prerequisite for any “independently reviewed RTL” statement. The current working computer has 9 CPUs, about 9.7 GiB memory and no GPU; no paid model use has been authorized. Do not start charged inference/training or publish artifacts merely because this plan exists.

## Research questions and claim boundaries

1. Can a fixed model, prompt, tool and compute budget produce functionally correct, reward-qualified candidate RTL in each family? This is a **pending model-difficulty experiment**, not established by the authored reference comparisons or a CPU template-selection smoke.
2. After actual policy-weight updates, does heldout parameter performance improve beyond an equal-budget frozen-policy and best-of-N no-training control? A scripted source selector, prompt edit, or reward-tuned template search does **not** count as policy training.
3. Do within-family generic-cell and cycle proxies rank physical area and latency tradeoffs across multiple verified candidates/configurations? The [ten-point TRAIN physical study](pilot-physical-calibration.md) provides five single-configuration area pairs, but no validated within-family ranking stability or core-latency correlation. The older two-point integer-RMS reference also cannot establish correlation for these five families.

All claims are conditional on exact task semantics and interfaces. “Test” below means **structural parameter holdout within a known family**, never an unseen circuit family, unseen design specification, or novel architecture contract. Frozen authored references have now been qualified at DEV/TEST parameters ([summary](../evidence/pilot-reference-holdout-qualification/summary.json)); those outcomes must stay out of a future model’s feedback and candidate-selection path. Several public evaluators also score proposed test values on an ordinary call. Thus only a future model whose entire feedback path is sealed before it sees any test result could be evaluated as blind on this split. Existing reference evidence is background, not a blind model test.

## Cohort and structural split

Candidate RTL bytes must remain identical across configurations in a family; only host-owned compile-time parameters change. Use distinct private operand/traffic seeds within each partition, paired exactly between candidate and fixed baseline. Never call seeded input replays an architectural holdout.

| Family | Train parameters | Development parameters | Test parameters | Contract retained |
|---|---|---|---|---|
| `gather` | DEPTH 16, 32 | DEPTH 64 | DEPTH 128, 256 | Four 8-bit-address read lanes, 32-bit words, mask compaction, write/read response rules and 1..64-cycle transaction contract. |
| `mshr` | ENTRIES 2, 4 | ENTRIES 6 | ENTRIES 8 | Four-word lines, four waiters/line, tagged client and external-memory channels, coordinated reset and 2048-cycle bound. |
| `sparse24_dot_requant` | G 1, 2, 4 | G 3, 5 | G 6, 7, 8 | Two-of-four selector encoding, exact signed INT8 dot/requant arithmetic and ready/valid contract. |
| `block_quant` | N 1, 2, 4, 8 | N 3, 5, 6, 7 | N 9 through 16 inclusive | Exact signed INT16 magnitude/exponent/ties-even INT8 result and ready/valid contract. |
| `hadamard_int8` | N 1, 2, 4 | N 8 | N 16 | Exact unnormalized Sylvester transform/order and ready/valid contract. |

These values are all legal under the current source contracts ([pilot](../chip_rl/contracts.md), [memory](../chip_rl/memory/spec.py), [sparse24](../chip_rl/sparse24/spec.py), [block quant](../chip_rl/block_quant/spec.py), [Hadamard](../chip_rl/hadamard_int8/spec.py)). They do **not** create a new task. In particular, the current pilot gather evaluator normally covers DEPTH 16/64/256 (and stress 32/128); MSHR normally includes ENTRIES 2/8; sparse24's existing development/heldout sets differ from this proposed split; block quant normally scores N 1/2/4/8/16; and Hadamard normally scores all five N. A `step` call on the current public APIs therefore cannot by itself enforce this proposed blind split; **do not expose those legacy APIs as the training tool** for a blind pilot. The separate [`chip_rl.pilot`](../chip_rl/pilot/) split-aware single-case path is implemented and has supported finite frozen-reference checks, but it still needs a model-facing leakage audit before blind use. A model-facing controller should reveal only train results during learning, only dev results during model selection, and no test metrics to the optimizer until the full candidate/model/analysis freeze. Test dimensions may be documented as legal specification parameters; blindness concerns feedback and candidate selection, not an implausible claim that nobody has heard of N=16. Preserve the existing contracts and public evaluator semantics; a split-aware runner is a separate experiment runner, not an unannounced change to the public reward. A tool that exposes test metrics, trace logs, synthesis artifacts, cache keys or private seeds to the candidate invalidates the blind-test claim. The [exploratory ten-design physical study](pilot-physical-calibration.md) used only **train** configurations as a method study; physical test-configuration measurements must wait until the candidate sources and analysis are frozen.

## Freeze, provenance and leakage control

Use a two-stage machine-readable freeze. **Before model generation**, commit SHA-256 of the repository commit; each baseline and alternative reference's emitted source for every parameter; contract/oracle/workload/simulation/synthesis/scorer/negative-control files; exact tool executables and versions (including Icarus, Yosys/ABC and synthesis scripts); Docker/container image if used; compiler flags, parameter values, clock/reset assumptions, resource limits and scoring gates; model identifier and immutable starting-weight checkpoint; prompts/system instructions; sampling settings; tool schema; train/dev/test seed derivation; rollout count, stop criteria and statistical analysis code. **After train/dev selection but before test feedback**, append the selected model checkpoint and the exact candidate source SHA-256 for each family, without changing the first-stage recipe. Hash the fully resolved recipe, not only a prose description. Record actual tool and output hashes again at execution and fail closed on mismatch. Store private test seeds, vectors, output traces and judge files outside the model/candidate's readable filesystem; publish only redacted digests after the blind decision. A cache hit is allowed only after matching source/config/tool/recipe fingerprints and must never suppress required fresh RTL and mapped simulation. Pair baseline and candidate on identical work; record all failures, timeouts and cache provenance rather than dropping them from denominators.

The freeze must also list preexisting public reports and legal dimensions the model might have encountered. No “unseen specification” claim is allowed. Existing authored reference results and human knowledge must be disclosed, but do not automatically contaminate a future model if test feedback is kept out of its optimization path. If the optimizer or candidate selector sees this experiment's test feedback before its second-stage freeze, reclassify that partition as development and design a new sealed test; changing only random traffic is insufficient to restore structural blindness. A post-result RTL, oracle, threshold or candidate-selection change requires a new version and an explicitly new experiment, retaining the first attempt and its failures.

## Gate 1: independent contract and evaluator review

An independent human RTL reviewer must inspect all five families with the [review packet](pilot-review-packet.md), returning named, dated pass/fail/unresolved findings and exact reviewed hashes. Independently derived hand vectors and any source/mapped/formal checks must be scoped separately. No reviewer has been contacted and no endorsement exists. The same freeze process applies to the test firewall: attempt to elicit test counters, cached netlists, seeds and raw logs from the agent side; verify the scorer cannot be controlled by `step({"rtl": ...})` or reset seed. Test evaluator changes with predeclared numerical, ordering, liveness and reset mutants and at least two valid architectures where available. Existing controls are useful starting points: gather `gather_order`/late-write/reset source generators (executed result must be verified), v27 MSHR delayed/retained-reset controls, sparse24 scalar decoder probes (not full-RTL proof), block-quant wrong `-32768` and ties-away controls, and Hadamard wrong-sign/lane-swap/truncation controls. Record both false rejection and false acceptance. A passing negative-control set is finite sensitivity evidence, not universal soundness.

## Gate 2: model-difficulty measurement (pending)

Use the **same immutable model**, task-neutral prompt skeleton, tool schema, sampling settings, wall/CPU limit, candidate count and source-repair/evaluator-call budget for all five families. Insert only each family’s normative contract and port/parameter facts into a predetermined prompt slot. Freeze a concrete rollout count `R` per family/partition and the per-rollout termination budget in the manifest **before any run**; do not choose them after inspecting pilot outcomes. Use independent model sampling seeds, no persistent conversation across rollouts, and no test feedback during source generation or selection. The model may see train diagnostics according to a frozen policy, dev only for predeclared model/prompt selection, and test exactly once after candidate freeze. A current CPU-only template selector cannot satisfy this gate; it neither estimates generative model difficulty nor shows learning. Paid model charges remain unauthorized.

For each family and parameter, report raw denominators and: compile/source-preflight pass, exact RTL pass, mapped pass, service qualification and positive-reward pass rates with binomial uncertainty intervals; treat timeout, missing tool and no candidate as failures. Report the **conditional** distribution of area ratio, completion-cycle ratio, stream II (where defined), latency and reward among functionally correct outputs, including median, quartiles, range and sample count; also show failures and all-run unconditional outcomes so conditioning cannot hide hard cases. Preserve workload and candidate hashes. Measure per-rollout elapsed wall seconds, process CPU seconds and peak RSS, and separate model generation, synthesis, source simulation, mapped simulation and cache lookup/hit time. Report token counts and token costs **only if observed from the provider or a verified local counter**; do not estimate them from characters or silently substitute a rate card. Report synthesis/simulation invocation counts and cache hit/miss breakdown. Do not compare reward magnitudes across unlike family scoring rules as if they were commensurate physical quality.

## Gate 3: physical proxy validation (pending)

For **each** family, freeze multiple functionally correct candidates spanning at least three distinct area/latency tradeoff points, including the fixed baseline and available alternatives, and evaluate them at multiple legal structural configurations. If the existing alternatives do not span three tradeoff points, prepare and verify more before correlation analysis; do not relax a hard reward gate to manufacture a sample. Hold the wrapper, PDK/library corner, clock definition, output load, input delay, synthesis constraints, floorplan/core boundary, placement density rule, routing effort and reporting protocol constant within each comparable family/configuration block. Version and hash all scripts, Liberty/LEF/PDK inputs, RTL and reports. Repeat physical runs or vary tool seeds according to a preregistered scheme so implementation noise is visible. Require valid route/DRC/LVS/equivalence status for a signoff-quality physical point; retain failed/incomplete routes in the accounting rather than silently dropping them.

Compare generic cells with final standard-cell area and compare cycle/proxy completion with **measured physical latency** defined in advance (for example cycles times a routed, justified achievable period), not slack at one loose clock target masquerading as Fmax. Report both dimensions and Pareto frontiers by configuration. Calculate Spearman rank association within comparable family/configuration strata with uncertainty intervals from candidate-level or paired hierarchical resampling; state the exact interval method and multiplicity. Report `n`, distinct ranks, ties, censored/failed routes, raw paired points and whether the candidate ranking changes with configuration. Do not pool heterogeneous families into one unqualified correlation or infer any correlation from the two integer-RMS physical-reference samples. The [completed exploratory five-family study](pilot-physical-calibration.md) adds five area pairs but only one TRAIN configuration and two sources per family, no repeated tool seeds, and I/O-to-I/O maximum setup paths under loose timing constraints. Its pooled ten-design Spearman value is descriptive and size-confounded, not Gate 3 validation. The [existing RMS study](rms-physical-reference-v1.md) is another cautionary example: it used a loose 100 ns clock and had incomplete reference-deck DRC, so its two points do not establish proxy validity.

## Gate 4: weight-updated policy training (pending)

Preregister an actual optimizer that **updates model weights**. Freeze starting checkpoint, architecture, train-only data/candidate collection, reward definition, optimizer/hyperparameters, sampling settings, tool access, holdout firewall, checkpoint selection rule and analysis script. Run at least **three independent training seeds**. State the fixed episode/evaluator-call/token or equivalent compute limit, wall-time cutoff, checkpoint schedule and early-termination rule **before** any training run. The same frozen model sampled without training is the no-training control. The best-of-`N` control receives the same `N` candidate samples and evaluation/selection budget as the trained policy; choose `N` before outcomes. Match pre/post heldout evaluation for sample count, decoding, tool budget, hardware class and evaluator revision. Evaluate all seeds and controls on untouched test parameters once after freeze, using paired private traffic where suitable. Report raw per-seed success and quality distributions, uncertainty intervals, all compute/resource use, failed runs and selection effects. A result that is only a template-selection smoke, prompt engineering, search over authored RTL, or a single training seed is **insufficient** for a learned-policy advantage claim.

The host currently has no GPU and no authorized model charges. Training or model calls therefore remain a proposed stage until an explicit execution environment, budget and authorization exist. No model-difficulty or training-improvement number should be filled in by extrapolation from reference RTL runs. The exploratory physical area correlation is separately reported with its confounding and timing limits; it is not a validated physical-proxy correlation.
